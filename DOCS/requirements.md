# GroundLink v2 요구사항 정의서

2026-11-10 · 임민규

> 원본: Claude Docs 문서 "GroundLink v2 요구사항 정의서". 이 파일은 Git 보관용 사본이다.

## 개요

GroundLink v2는 위성 1개(SAT-001)의 상태를 실시간으로 받아 보여주고, 지난 1주일 기록을 기간별로 요약해 차트로 보여주는 WPF 관제 앱이다. 데이터는 시뮬레이터(C# 콘솔, TCP 서버) → WPF(TCP 클라이언트) → SQL Server 순서로 흐른다.

- **사용자**: 관제사 1명, PC 1대
- **목적**: 학습과 포트폴리오. 렌더링 성능과 UI 개선이 핵심이고, 네트워크·DB·멀티스레드·MVVM을 직접 구현한다.
- **범위**: 위성 1개, 값 2개(배터리, 온도)
- **범위 밖**: 여러 위성, 위성에 명령 보내기, 로그인, 여러 PC 동시 사용

| 항목 | 내용 |
| --- | --- |
| OS | Windows 10 20H2 |
| 개발 도구 | Visual Studio 2022 |
| 런타임 | .NET 8, WPF |
| DB | SQL Server 2025 Express (`localhost\SQLEXPRESS`, Windows 인증), DB 이름 `MonitorDB` |
| 차트 | ScottPlot.WPF (MIT, 무료) |
| 저장소 | GitHub `GroundLink_Monitor` (로컬 폴더 이름 `GroundLink`) |

## 화면 구성

화면의 모든 영역은 관제사의 질문 하나에 답한다. 코드를 짤 때는 "이 코드는 어느 영역의 어떤 질문을 위한 것인가"를 이 표에서 찾는다.

| 관제사의 질문 | 화면 영역 | 단계 |
| --- | --- | --- |
| 지금 위성과 연결이 살아 있나? | ⓪ 상단 상태 바 | 6단계 |
| 지금 위성 상태가 괜찮나? | ① 현재 값 패널 | 2단계(DB 조회), 5단계(실시간) |
| 방금 전부터 어떻게 변하고 있나? | ② 실시간 차트 | 5단계 |
| 지난 하루·일주일 동안 위험한 적이 있었나? | ③ 과거 기록 차트 + 기간 버튼 | 3단계 |

완성 화면 배치:

```
┌──────────────────────────────────────────────────────────────┐
│ ⓪ 상태 바   SAT-001 · 연결됨 · 마지막 수신 시각   (6단계)     │
├────────────────────┬─────────────────────────────────────────┤
│ ① 현재 값          │ ② 실시간 차트                  (5단계)  │
│                    │   최근 N분을 1초마다 흐르게 표시         │
│ 배터리 62.3 % 정상 │   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~    │
│ 온도 11.8 °C 정상  ├─────────────────────────────────────────┤
│                    │ ③ 과거 기록 차트   ← 지금 만드는 중     │
│ 기준을 벗어나면    │   [1시간] [1일] [1주일]                 │
│ 색이 바뀜          │   평균·최소·최대 선 + 경고 기준선       │
│ (2단계·5단계)      │                                (3단계)  │
└────────────────────┴─────────────────────────────────────────┘
```

③이 지금 만드는 3단계 영역이고, ⓪과 ②는 5~6단계에서 채운다.

참고 디자인: Claude 디자인 캔버스 "GroundLink 관제 화면" (예시 디자인). 화면 이미지는 아직 넣지 않고, 아래 UI 요구사항에 글로 정리한다.

## 기능 요구사항

기능은 10개이고, 현재 F-01이 끝났고 F-03·F-04를 진행 중이다. 표의 영역 번호는 화면 구성의 ⓪~③이다.

| ID | 요구사항 | 상세 | 영역 | 단계 | 상태 |
| --- | --- | --- | --- | --- | --- |
| F-01 | 현재 값 표시 | 배터리, 온도, 마지막 기록 시각 | ① | 2 | 완료 |
| F-02 | 경고 표시 | 기준을 벗어나면 값의 색을 바꾸고 "경고"를 표시 (기준: 데이터 요구사항) | ① | 3 이후 | 예정 |
| F-03 | 과거 기록 차트 | 기간 버튼 1시간 / 1일 / 1주일 | ③ | 3 | 진행 중 |
| F-04 | 기간별 요약 조회 | 1시간 = 1분, 1일 = 5분, 1주일 = 30분 단위. 평균·최소·최대를 함께 그림 | ③ | 3 | 진행 중 |
| F-05 | 경고 기준선 | 차트에 기준값 가로선을 그어 "선 밖으로 나간 적 있나"를 바로 보이게 함 | ③ | 3 | 예정 |
| F-06 | 위성 시뮬레이터 | TCP 서버 127.0.0.1:5000, 1초마다 JSON 한 줄, 이전 값에서 조금씩 변함 | - | 4 | 예정 |
| F-07 | 실시간 수신 | 받는 스레드를 따로 두고, 화면은 Dispatcher로 갱신 | ① | 5 | 예정 |
| F-08 | 실시간 차트 | 최근 N분을 1초마다 흘러가게 표시 (N 결정 필요) | ② | 5 | 예정 |
| F-09 | 수신 데이터 저장 | 받은 데이터를 모아서 한 번에 DB에 저장 | - | 6 | 예정 |
| F-10 | 연결 상태·재접속 | 끊김을 감지해 ⓪에 표시하고 자동으로 다시 접속 | ⓪ | 6 | 예정 |

## UI 요구사항

예시 디자인을 목표로 하되, **3~6단계는 기본 모양으로 기능만 만들고, 디자인은 7단계(UI 개선)에서 입힌다.** 예시 디자인과 픽셀 단위로 같을 필요는 없다.

### 화면 요소

| ID | 요소 | 내용 | 영역 | 단계 |
| --- | --- | --- | --- | --- |
| U-01 | 테마 | 다크 테마. 배경 `#0B1220`, 카드 `#111A2B`, 테두리 `#1F2A3D`, 강조 `#38BDF8`, 경고 `#F59E0B`, 정상 `#34D399` | 전체 | 7 |
| U-02 | 폰트 | 글자는 맑은 고딕, 숫자는 Consolas (둘 다 윈도우 기본 폰트) | 전체 | 7 |
| U-03 | 카드 | 영역마다 둥근 모서리 카드로 묶음 | 전체 | 7 |
| U-04 | 상태 바 | 위성 ID, 연결 상태(연결됨/끊김), 서버 주소, 마지막 수신 시각, 수신 주기 | ⓪ | 6 |
| U-05 | 현재 값 카드 | 큰 숫자 + 단위, 상태 배지(정상/경고), 게이지(경고 기준 눈금 표시), 최근 5분 최저·최고 | ① | 2 → 7 |
| U-06 | 경고 기준 카드 | 배터리·온도 경고 기준값 표시 | ① | 7 |
| U-07 | 실시간 차트 | 배터리·온도 차트 2개 나란히, 경고 점선, x축 "5분 전 ~ 지금" | ② | 5 |
| U-08 | 과거 기록 차트 | 평균선 + 최소~최대 띠 + 경고 점선 + "경고 60 %" 글자 | ③ | 3 |
| U-09 | 과거 기록 요약 칸 | 기간 중 최저값, 경고선 아래로 내려간 구간 수, 그린 점 수 / 원본 줄 수 | ③ | 3 |
| U-10 | 기간 버튼 | 1시간 / 1일 / 1주일, 선택된 버튼 강조. 처음엔 일반 버튼 3개, 붙어 있는 모양은 7단계 선택 사항 | ③ | 3 → 7 |
| U-11 | 화면 배치 | 데스크톱 고정 배치. 창 폭에 따른 재배치는 하지 않음 | 전체 | 7 |

### 구현 담당과 난이도

차트 안쪽만 ScottPlot이 그리고, 나머지는 모두 WPF(XAML)로 만든다.

| 요소 | 담당 | 난이도 | 비고 |
| --- | --- | --- | --- |
| 꺾은선 (평균, 실시간) | ScottPlot | 쉬움 | 3-1에서 확인 |
| 최소~최대 띠 | ScottPlot | 보통 | 두 선 사이 채우기(FillY) |
| 경고 점선 + 글자 | ScottPlot | 쉬움 | 가로선(HorizontalLine) |
| 다크 배경, 격자·축 색 | ScottPlot | 쉬움~보통 | 색 설정 |
| 1초마다 흐르는 차트 | ScottPlot | 보통 | 실시간용 기능(DataStreamer, DataLogger) |
| x축 글자 ("24시간 전 … 지금") | ScottPlot | 보통 | 눈금 글자 직접 지정 |
| 둥근 카드, 큰 숫자, 배지 | WPF | 쉬움 | `Border` + `TextBlock` |
| 게이지 + 경고 눈금 | WPF | 보통 | `Grid` 안에 막대 겹치기 |
| 붙어 있는 기간 버튼 | WPF | 어려움 | 스타일 템플릿 직접 작성 필요 |

차트 여백, 축 위치 같은 세부는 ScottPlot 기본 배치를 따르므로 예시 디자인과 다를 수 있다. 차트 테두리 제거처럼 확인하지 못한 설정은 구현하면서 확인한다.

## 데이터 요구사항

값은 배터리 잔량과 배터리 온도 2개이고, 경고 기준과 더미 데이터는 공개된 실제 위성 비행 데이터와 리뷰 논문을 근거로 정했다.

### 텔레메트리 항목

| 항목 | DB 칸 | 단위 | 정상 범위 (더미 데이터) | 경고 기준 | 경고 근거 |
| --- | --- | --- | --- | --- | --- |
| 배터리 잔량 | `Battery` FLOAT | % | 약 85~100 | 60 미만 | LEO 1바퀴 방전 깊이(DoD) 상한 40% 초과 [2] |
| 배터리 온도 | `Temperature` FLOAT | °C | 약 12~18 | 0 미만 또는 40 초과 | 리튬이온 충전 하한 0°C, LEO 배터리 온도 범위 0~40°C [2] |

경고는 1단계만 둔다. 2단계(위험) 기준은 근거 자료가 없어서 정하지 않았다.

### 더미 데이터 모델 (`02_seed_week.sql`, 시뮬레이터 공통)

위성은 햇빛에서 충전하고 그늘(일식)에서 방전한다. 값은 "궤도 안에서 몇 초째인가"로 계산한다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 궤도 주기 | 5,669초 (약 94.5분) | GOMX-4 실측 [1] |
| 그늘 비율 | 0.31 → 그늘 1,757초, 햇빛 3,912초 | GOMX-4 실측 [1] |
| 배터리 잔량 | 햇빛 85 → 100 (충전), 그늘 100 → 85 (방전) | 충방전 원리 |
| 1바퀴 방전 깊이 | 15% | LEO 일반 10~40% [2] 범위 안에서 선택 (가정) |
| 배터리 온도 평균 | 15°C | 배터리 운용 범위 10~20°C [3]의 가운데 (가정) |
| 온도 1바퀴 진폭 | ±3°C (햇빛 상승, 그늘 하강) | GOMX-4 실측 2.54~3.53°C [1] |
| 위상 기준 | 2026-01-01 00:00:00 (로컬) | SQL과 시뮬레이터가 같은 값을 써서 과거·실시간 데이터가 이어짐 |
| 잡음 | 잔량 ±0.1, 온도 ±0.2 | 가정 |

단순화: 실제로는 충전 끝에 속도가 느려지지만, 여기서는 일정한 속도로 오르내린다.

출처:

1. [Battery Current and Temperature Mission Profiles for CubeSats at Low Earth Orbit (Aalborg Univ., 2022)](https://vbn.aau.dk/ws/files/467286916/2022_Battery_Current_and_Temperature_Mission_Profiles_for_CubeSats_at_Low_Earth_Orbit.pdf): GOMX-3, GOMX-4A/B 궤도 원격측정 분석
2. [A Review of Battery Technology in CubeSats and Small Satellite Solutions (Energies, 2020)](https://s3vi.ndc.nasa.gov/ssri-kb/static/resources/energies-13-04097-v2.pdf): LEO DoD 10~40%, LEO 배터리 온도 0~40°C, 리튬이온 충전 0°C·방전 -20°C까지
3. [Spacecraft thermal control (Univ. of Hawaii 교재)](https://pressbooks-dev.oer.hawaii.edu/epet302/chapter/8-3/): 배터리 운용 범위 10~20°C
4. [AAC Clyde Space OPTIMUS 배터리 데이터시트](https://www.aac-clyde.space/wp-content/uploads/2021/10/AAC_DataSheet_Optimus.pdf): 큐브샛 배터리 운용 온도 -10~+50°C (참고)

### 테이블 `dbo.Telemetry`

| 칸 | 자료형 | 설명 |
| --- | --- | --- |
| Id | BIGINT IDENTITY, PK | 줄 번호 |
| SatelliteId | VARCHAR(16) | 위성 ID, 예: `SAT-001` |
| RecordedAt | DATETIME2(0) | 기록 시각 (초 단위) |
| Battery | FLOAT | 배터리 (%) |
| Temperature | FLOAT | 배터리 온도 (°C) |
| Source (예정) | TINYINT | 1 = 미리 넣은 데이터, 2 = 소켓으로 받은 데이터. 6단계에서 추가 |

- 인덱스: `IX_Telemetry_Sat_Time` = (SatelliteId, RecordedAt) INCLUDE (Battery, Temperature)
- 미리 넣은 데이터: 604,800줄 (7일 × 86,400초, 1초 간격)
- 현재 PK가 Id라서 같은 시각의 줄이 두 번 들어가는 것을 막지 못한다. 6단계 재접속 때 다시 본다.

### 전송 형식 (시뮬레이터 → WPF)

한 줄에 JSON 하나, 줄바꿈으로 구분한다. 필드 이름은 제안이고 4단계 전에 확정한다.

```json
{"satelliteId":"SAT-001","recordedAt":"2026-11-10T14:05:12","battery":62.3,"temperature":11.8}
```

## 비기능 요구사항

성능 목표 수치는 첫 측정 후에 정한다. 지금은 "무엇을 어떻게 잴지"만 정해둔다.

| ID | 항목 | 기준 | 확인 방법 |
| --- | --- | --- | --- |
| N-01 | 차트 점 개수 | 기간과 상관없이 선 하나당 약 340개 이하 (1시간 약 60, 1일 약 288, 1주일 약 337) | 조회한 구간 수를 화면에 표시 |
| N-02 | 과거 차트 응답 시간 | 목표는 첫 측정 후 결정 | 조회 시간과 그리기 시간을 따로 측정 (Stopwatch) |
| N-03 | UI 멈춤 없음 | DB 조회·수신 중에도 창 이동과 버튼이 반응 | 7단계에서 스레드 분리 전후 비교 |
| N-04 | 저장 방식 | 받은 데이터를 모아서 한 번에 저장 (주기·개수 결정 필요) | 저장 횟수와 걸린 시간 기록 |
| N-05 | 재접속 | 끊기면 일정 간격으로 자동 재시도 (간격 결정 필요), 앱은 꺼지지 않음 | 시뮬레이터를 껐다 켜서 확인 |
| N-06 | 자원 정리 | DB 연결·소켓은 `using`으로 닫음 | 코드 리뷰 |
| N-07 | 구조 | 처음엔 code-behind, 7단계에서 MVVM으로 옮김 | 옮기기 전후 코드 비교 |

## 결정

아직 정해야 할 것은 4개이고, 실시간 차트 길이가 가장 먼저다(5단계 전).

### 결정 필요

- [x] 배터리·온도 경고 기준값 (데이터 요구사항 참고)
- [x] JSON 필드 이름: `satelliteId`, `recordedAt`, `battery`, `temperature`
- [ ] 실시간 차트에 보여줄 길이, 최근 몇 분 (5단계 전, 예시 디자인은 5분)
- [ ] 저장 주기: 몇 초 또는 몇 줄마다 (6단계 전)
- [ ] 재접속 간격 (6단계 전)
- [ ] 성능 목표 수치 (첫 측정 후)

### 결정 기록

| 날짜 | 결정 | 이유 |
| --- | --- | --- |
| 2026-11-10 | 경고 기준: 배터리 60% 미만, 온도 0°C 미만 또는 40°C 초과 (1단계) | 출처 있는 값만 사용. 이전 제안값(30%, -10~30°C)은 근거 없이 정한 값이라 폐기 |
