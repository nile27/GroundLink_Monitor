## 사례 1. 차트의 한글이 □로 표시됨

- **문제**: 과거 기록 차트의 제목·범례·x축(오전/오후) 한글이 □로 나옴 (`DOCS/test-log.md:40`)
- **원인**: ScottPlot은 글꼴을 이름으로 못 찾으면 **에러 없이** 한글이 없는 기본 글꼴로 대체한다. "Malgun Gothic" 이름 검색이 실패한 것으로 판단 (`test-log.md` "한글 □ 표시 해결 과정" 아래 원인 문단)
- **시도와 해결**: 이름 지정 → 위치 변경 → `Font.Automatic()` 세 번 실패 후, 글꼴 파일을 직접 등록(`Fonts.AddFontFile("KoreanFont", malgun.ttf)`)하고 날짜 축을 만든 **뒤에** `Font.Set` 호출 (`test-log.md` 시도 표, `GroundLink/Charts/ChartDrawer.cs:25-28, 232-249`)
- **근거 커밋**: `dd18135` "feat: 실시간 현재 값 표시 + 경고, 차트 한글 글꼴 수정"
- **결과**: 한글 정상 표시 (`test-log.md:40` 상태 "해결", 이후 화면 `portfolio/screenshots/01`). **측정값 없음**
- **면접 포인트**: 라이브러리가 실패를 조용히 넘기는 경우 → 소스·동작을 확인해 원인을 좁힌 과정
- **본인 판단 여부**: (빈칸)

## 사례 3. 1주일 차트가 위아래로만 왔다갔다해서 읽을 수 없음

- **문제**: 1주일 30분 평균 차트가 위아래 진동만 보임 (`test-log.md:41`)
- **원인**: 1주일에 궤도가 약 107바퀴 → 파동 107개가 차트 폭에 몰림. 30분 구간이 94.5분 궤도와 맞지 않아 구간마다 다른 위치가 잡힘 (`test-log.md:41`, `requirements.md:210`)
- **해결**: 1주일은 시간 구간 대신 **궤도 1바퀴 단위**로 요약. SQL `DATE_BUCKET(SECOND, 5669, RecordedAt, 궤도 기준점)`으로 구간 하나 = 바퀴 하나, 90% 이상 찬 바퀴만 사용(`HAVING`). 1일은 파동 약 15개라 5분 평균 유지 (`GroundLink/Data/TelemetryRepository.cs:131-166`, `requirements.md:210-211`)
- **근거 커밋**: 없음 [커밋 전]
- **결과**: **측정값 없음**. 실제 화면 확인(T-07-3)도 미실시 (`test-log.md:222`)
- **면접 포인트**: "무엇을 보여줄 차트인가"(진동 vs 바퀴별 최저값 추세) 판단, `DATE_BUCKET` origin 인자
- **본인 판단 여부**: (빈칸)

## 사례 4. UI 스레드에서 소켓을 받아 창이 "응답 없음"

- **문제**: 시뮬레이터 연결 후 화면 갱신 안 됨, 버튼·창 이동 불가, "응답 없음" (`test-log.md:120-125`, T-05-1)
- **원인**: 블로킹 호출 `ReadLine()`을 UI 스레드에서 실행 → UI 스레드가 메시지 처리를 못 함
- **해결**: 수신 전용 스레드(`new Thread`, `IsBackground`)에서 받고, 화면 변경만 `Dispatcher`로 UI 스레드에 넘김 (현재 코드: `GroundLink/Network/TelemetryReceiver.cs:46-53`, `GroundLink/MainWindow.xaml.cs:57`)
- **근거 커밋**: `dd18135` (`MainWindow.xaml.cs` 변경. 직전 `a88b761` "별도 스레드 수신"은 test-log만 추가)
- **결과**: T-05-2 "통과 (일부)" — 수신 값 갱신은 확인, 스레드 번호·연결 중 창 이동은 미기록 (`test-log.md:131`). **측정값 없음**
- **면접 포인트**: UI 스레드 모델, 블로킹 I/O, Dispatcher (→ 03-threading.md. 이력서에는 [개발 중])
- **본인 판단 여부**: (빈칸)

## 사례 5. 차트 그리기 시간을 Stopwatch로 잴 수 없음

- **문제**: `Refresh()` 앞뒤로 시간을 재면 실제 그리기 시간이 아님
- **원인**: `WpfPlot.Refresh()`는 `InvalidateVisual`만 호출하고 실제 그리기는 WPF 화면 갱신 때 일어남 (ScottPlot.WPF 5.1.59 DLL에서 호출 목록 확인, `requirements.md:205`)
- **해결**: ScottPlot `RenderManager.RenderFinished` 이벤트의 `Elapsed`로 측정 (`GroundLink/MainWindow.xaml.cs:81-83`, `GroundLink/Charts/ChartDrawer.cs:101` 주석)
- **근거 커밋**: 없음 [커밋 전]
- **결과**: 1건/초 조건에서 "차트 그리기 2회/초, 평균 2.0 ms (최대 3.0)" 화면 표시 (`portfolio/screenshots/01_main_receiving.png` 상단 성능 줄). **비교 대상(전/후)이 없어 개선 수치는 없음**
- **면접 포인트**: "측정 도구가 무엇을 재는지 먼저 확인" — 비동기 렌더링
- **본인 판단 여부**: (빈칸)

## 사례 6. 시뮬레이터가 1초 100건을 못 보냄 (Thread.Sleep 정밀도)

- **문제**: `Thread.Sleep(10)`으로는 초당 100건이 나오지 않음
- **원인**: Windows 기본 타이머 해상도 때문에 `Thread.Sleep`이 약 15.6 ms 단위로 쉼 (`GroundLink.Simulator/Program.cs:81` 주석)
- **해결**: 보낼 시각을 "시작 시각 + 순번 × 간격"으로 정하고, 깨어날 때마다 밀린 건수만큼 몰아서 보냄. 시각이 간격대로 붙어 DB 고유 인덱스에서 겹치지 않음 (`Program.cs:80-96, 124`)
- **근거 커밋**: 없음 [커밋 전]
- **결과**: **측정값 없음** (문서에 기록된 측정 없음. `--hz 100` 실행 후 콘솔의 "최근 1초 N건 보냄" 줄(`Program.cs:116-121`)로 직접 확인해 기록할 것)
- **면접 포인트**: OS 타이머 해상도, 드리프트 없는 주기 작업
- **본인 판단 여부**: (빈칸)

## 사례 7. 1초에 여러 건 받으면 DB가 조용히 버림

- **문제**: 1초에 10건 이상 받으면 같은 초에 여러 건 → 1건만 저장될 수 있음
- **원인**: 시각 칸이 1초 단위(`DATETIME2(0)`, `DB/01_create_table.sql`)이고, (위성, 시각) 고유 인덱스에 `IGNORE_DUP_KEY = ON`이라 겹친 줄은 **에러 없이** 버려짐 (`DB/04_unique_time.sql:21-24`, `requirements.md:203`)
- **해결**: 시각을 1/1000초 단위(`DATETIME2(3)`)로 변경. 인덱스가 걸린 칸은 타입을 못 바꿔 "인덱스 삭제 → 타입 변경 → 재생성" (`DB/05_time_milliseconds.sql`)
- **근거 커밋**: 없음 [커밋 전]
- **결과**: **측정값 없음** (고속 저장 건수 확인 기록 없음)
- **주의**: 작업 폴더의 `05` 스크립트는 `DROP INDEX`에 `IF EXISTS`가 없는 버전이라 두 번 실행하면 오류가 난다 (`DB/05_time_milliseconds.sql:13`)
- **면접 포인트**: 조용한 데이터 유실, `IGNORE_DUP_KEY`의 장단점
- **본인 판단 여부**: (빈칸)

## 사례 8. 중복 1건 때문에 저장 묶음 전체가 실패할 수 있음

- **문제(예방)**: 10건을 한 트랜잭션으로 저장하는데, 그중 1건이 중복이면 전체가 롤백되고 저장 대기 리스트가 비워지지 않아 다음에도 계속 실패할 수 있음

- **해결**: 고유 인덱스에 `IGNORE_DUP_KEY = ON` → 중복 줄만 건너뛰고 나머지 저장 (`DB/04_unique_time.sql`, `requirements.md:213`)
- **근거 커밋**: `28a7fa3` "feat: 중복 저장 방지 인덱스"
- **결과**: **측정값 없음**. 실제로 중복이 발생한 기록도 없음 (예방 조치). T-06-2 "통과 (결과 화면 미기록)" (`test-log.md:175`)
- **본인 판단 여부**: (빈칸)
